# Cheevos 🪙

A fantasy-RPG-themed **achievement tracker for a child**. Chores and habits become
video-game "achievements": each is a task (optionally repeated N times) worth a
number of gold points on completion. Gold is spent on rewards in the Treasure
Vault. Parents configure everything behind a password.

Designed to run on a home server and be reached over the LAN at
`http://<server>/cheevos`.

## Features

- **Quest Board** (child): tap a quest once per day to make progress; tap again
  the same day to undo a misclick. Completing a quest awards gold and sends it to
  the Hall of Fame.
- **Treasure Vault** (child): redeem rewards you can afford. One-time rewards are
  retired after redemption; repeatable rewards stay.
- **Hall of Fame** (child): a trophy gallery of completed quests.
- **Parent console** (password): add/edit/delete quests & rewards (including
  adjusting "done so far"), an icon picker, and a redemption history to fulfill.
- **Gold balance** shown prominently with a coin, and always derived from the
  data (completed quests minus redemptions) — it can never drift.
- **~40 bundled icons** (fantasy + chores + kid rewards) from game-icons.net.

## Tech

Node + Express + SQLite (`better-sqlite3`), no build step. Express serves the
themed static frontend and a JSON API, both under a configurable base path. See
[the design/plan](#) for details; the code is organized as:

```
server.js          Express app: base-path mount, static, API, sessions, CSP
src/               config, db (+migrations), auth, validation, business logic
src/routes/        achievements, rewards, admin, icons
public/            HTML pages, theme.css, JS modules, icons/
scripts/           set-password.js, fetch-icons.js
test/              business-rule tests (node:test)
deploy/            systemd unit + nginx snippet
```

## Quick start (local dev)

```bash
npm install
npm run fetch-icons          # download the icon library (needs internet)
npm run set-password -- "your-parent-password"
npm start                    # → http://localhost:3000/cheevos/
```

Run the tests:

```bash
npm test
```

## Deploy on Ubuntu

1. **Get the code & deps** (e.g. into `/opt/cheevos`):
   ```bash
   sudo mkdir -p /opt/cheevos && sudo chown $USER /opt/cheevos
   git clone <repo> /opt/cheevos   # or copy the files
   cd /opt/cheevos
   npm ci
   npm run fetch-icons
   ```
2. **Configure**: set the parent password (this also creates `config/config.json`
   with a persistent session secret):
   ```bash
   npm run set-password -- "your-parent-password"
   ```
   Edit `config/config.json` if you want a different `port` or `basePath`.
3. **Service user & permissions**:
   ```bash
   sudo useradd --system --no-create-home cheevos
   sudo chown -R cheevos:cheevos /opt/cheevos
   ```
4. **systemd**:
   ```bash
   sudo cp deploy/cheevos.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now cheevos
   ```
5. **nginx**: paste `deploy/nginx-cheevos.conf` into your `server { }` block, then
   `sudo nginx -t && sudo systemctl reload nginx`.

Now visit `http://<server>/cheevos/`.

## Configuration (`config/config.json`)

| Key                 | Meaning                                             |
|---------------------|-----------------------------------------------------|
| `port` / `host`     | Where Node listens (default `127.0.0.1:3000`).      |
| `basePath`          | URL prefix (default `/cheevos`; `"/"` to serve root)|
| `sessionSecret`     | Signs the admin session cookie (set automatically). |
| `adminPasswordHash` | scrypt hash of the parent password (set by script). |

Any key can be overridden by an env var: `PORT`, `HOST`, `BASE_PATH`,
`SESSION_SECRET`, `ADMIN_PASSWORD_HASH`, `DB_FILE`. The SQLite file defaults to
`data/cheevos.db` and is created/migrated on first start.

## Security notes

LAN-only, hardened against casual web vulnerabilities (not for internet exposure):

- Parameterized SQL everywhere (no injection); strict input validation.
- XSS-safe rendering (text via `textContent`, never `innerHTML`) + a self-only
  Content-Security-Policy and `helmet` headers.
- Parent password stored as a scrypt hash; admin session cookie is httpOnly +
  SameSite=Strict; state-changing admin requests require a CSRF token; the login
  route is rate-limited.
